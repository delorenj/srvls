- (decision) Use hexagonal architecture for host integration boundaries plus a unidirectional Elm-style Model/Event/Update/View loop for ratatui. Binds all modules; prevents collectors, renderers, and TUI state from owning conflicting domain behavior.
- (decision) Define one provider-neutral Entry aggregate composed from stable identity, display name, kind/scope, status/health, optional schedule, provenance, capabilities, provider metadata, observations, and diagnostics. Provider-specific adapters compose facets into Entry; no inheritance-shaped type hierarchy. Binds collectors, grouping, renderers, and actions; prevents six incompatible provider models.
- (decision) Ports live inward and adapters implement Collector, Inspector, ActionExecutor, and CommandRunner. Domain imports no ratatui, clap, serde wire-format, subprocess, or provider modules. Binds dependency direction; prevents infrastructure and presentation concerns from leaking into domain policy.
- (decision) Stack inference is a Strategy pipeline producing evidence-scored candidate keys: explicit provider-native metadata first, normalized source/location second, conservative name similarity last. A deterministic resolver selects the highest-confidence group, exposes confidence/reasons, and leaves ambiguous entries ungrouped. Binds default grouping; prevents ad-hoc renderer heuristics and false-positive stacks.
- (decision) Semantic name grouping requires at least three members sharing a non-generic normalized prefix of at least two tokens; replica/instance numbers and provider suffixes may be stripped, but environment words and arbitrary substrings may not be silently discarded. Provider-native and shared-source evidence may form smaller groups. Binds similarity strategy; prevents accidental grouping of unrelated generic services.
- (decision) All inventory collection returns InventorySnapshot containing entries plus typed diagnostics. Collectors run concurrently behind bounded deadlines; failure or privilege denial is visible in TUI and stderr, and --strict converts any collector error to nonzero exit. Binds collection and errors; prevents missing subsystems from looking like a healthy empty host.
- (decision) Interactive action flow uses Command objects executed only through ActionExecutor after capability checks; destructive disable/delete requires a TUI confirmation, while direct CLI verbs preserve current explicit-command behavior. Every subprocess uses argv arrays, timeouts, output caps, and no shell. Binds lifecycle mutation; prevents duplicated unsafe command construction and shell injection.
- (decision) When stdout is a TTY, bare srvls opens ratatui; when non-TTY, bare srvls emits the legacy table. --table, --json, --prom, and --md are non-interactive and never emit ANSI, icons, or logs to stdout. Binds mode selection; prevents automation breakage and corrupted machine output.
- (decision) Centralize visual semantics in Theme and IconSet. Status color is the primary signal, provider icon is secondary, text labels always remain; honor NO_COLOR and offer an ASCII icon set so meaning never depends on color or glyph support. Binds TUI widgets; prevents inconsistent styling and inaccessible status-only color.
- (decision) Keep the flat external EntryV1 serialization contract separate from the richer domain Entry. Export presenters map domain snapshots to existing JSON/Prometheus/Markdown/table contracts; grouped export is opt-in and versioned later. Binds compatibility outputs; prevents internal evolution from silently breaking scripts.
- (decision) Use one binary crate with module boundaries domain, application, ports, adapters, presentation, and cli. Introduce workspace crates only after an independently reusable component reaches the Rule of Three. Binds project structure; prevents premature multi-crate and trait abstraction overhead.
- (decision) Use synchronous Rust with scoped worker threads/channels for concurrent collectors and TUI refresh; do not adopt Tokio absent a real async I/O requirement. Binds execution model; prevents dual runtimes and needless async complexity.
- (decision) Tests are deterministic below the host boundary: parser fixtures, fake ports, grouping property/table tests, presenter golden files, and ratatui TestBackend snapshots. Binds verification; prevents environment-sensitive CI and UI regressions.

- (decision) Amend grouping contract: normalize names with Unicode lowercase; split on non-alphanumeric separators and letter-number boundaries; remove only provider suffix tokens service, timer, scope, target and terminal replica tokens matching instance/ordinal patterns; never discard environment tokens. Evidence tiers are absolute: provider-native 300, exact normalized source 200, semantic prefix 100. Lower tiers never outweigh higher. Within a tier choose more members, then longer prefix/source specificity, then lexicographically smallest canonical key. Groups do not merge transitively across candidate keys.
- (decision) Define StackGroupId as evidence-kind plus normalized evidence key, with percent-encoded UTF-8 canonical form. Labels derive from provider project/namespace, source basename, or joined semantic prefix; duplicate labels receive provider/source disambiguation. Group identity persists while its winning evidence key persists, not by member set.
- (decision) Define EntryId as a typed tuple (provider, scope, native locator, occurrence). Provider adapters own canonical native locators: systemd full unit name; Docker immutable full container ID; PM2 numeric process ID plus PM2_HOME scope; cron source plus zero-based physical line and hash of exact schedule/user/command with occurrence index for duplicates. Encoding is percent-encoded UTF-8 components and is process-visible but not a promised durable external ID in v1.
- (decision) Collection buckets merge in fixed legacy order cron, systemd-system services/timers, systemd-user services/timers, Docker, PM2; each bucket sorts by legacy type then name then EntryId. Completion order never affects snapshots. Presenters retain current provider/type ordering and formatting through golden compatibility fixtures.
- (decision) Each collector returns CollectorReport with generation, entries, outcome Success|Partial|Unavailable|Denied|TimedOut|Failed, and scoped diagnostics. Snapshot diagnostics own all diagnostics; Entry holds diagnostic IDs only. --strict exits nonzero for Partial, Denied, TimedOut, or Failed, not Unavailable for optional absent tools. Failed refreshes never carry old entries forward as current; the TUI retains the last good snapshot visibly marked stale while showing the new failed report.
- (decision) TUI refreshes have monotonic generation IDs; only the latest requested generation may replace the displayed snapshot. Selection and confirmation targets bind EntryId plus source snapshot generation, never row indexes. Revalidation must resolve the same current native identity immediately before mutation or abort as stale.
- (decision) CommandRunner owns child termination and reaping: hard deadline, byte caps, nonzero/signal/UTF-8/truncation result semantics, kill process group on timeout when supported, and always wait. A bounded worker pool limits collectors. Dropping a channel result only suppresses stale delivery and is never treated as cancellation.
- (decision) Groups are read-only projections in v1. Lifecycle actions target individual entries only. Public disable remains the CLI verb but resolves to typed provider-native intent classified as systemd disable, Docker stop, or destructive PM2 delete. TUI confirms stop and disable/delete, while start/restart do not; action result distinguishes executed-and-verified, executed-unverified, refused, stale, and failed.
- (decision) TUI actions follow plan, capability/authorization preflight, confirmation, identity revalidation, execute, verify via targeted refresh, and result. Intrinsic provider support and observed authorization are separate. The binary never elevates itself; root collection and system mutations use sudo -n. TUI never permits an interactive password prompt in raw mode.

- (decision) Grouping resolver algorithm: candidates have tier, specificity integer (path component count or semantic token count), canonical key, and sorted member IDs. Sort by tier desc, current unclaimed member count desc, specificity desc, key asc; greedily claim unassigned members. Recompute residual count at selection; form native/source groups with >=2 residual members and semantic groups with >=3; discard smaller residuals entirely. One entry belongs to at most one group.
- (decision) CollectorReport includes Availability Required|Optional and sub-operation reports tagged Required|Advisory. Shared reducer: all successful => Success; any usable entries plus any required/advisory fault => Partial; no usable entries selects highest severity Failed > TimedOut > Denied > Unavailable. Subsidiary diagnostics are never hidden. Strict fails Partial/Failed/TimedOut/Denied and Required Unavailable; Optional Unavailable alone does not fail.
